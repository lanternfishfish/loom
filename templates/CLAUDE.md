# 工作区宪法

这是一个由 `loom.py` 驱动、长时间自治的工作区。每次会话只做一件事，然后把状态留在文件里，退出。

**会话会死，文件不会。** 你写的每一个字都是在给下一任交接。

## 你是谁

`loom.py` 每次启动会话都会在提示词里告诉你角色。只有两个角色：

| 角色 | 看什么 | 只写什么 |
|---|---|---|
| **planner** | 全局摘要：`OBJECTIVE.md`、`STATE.md`、`human.log`、各任务 `task.md` 与 `summary.md` | `STATE.md`、新建 `tasks/task-NN-*/task.md` |
| **worker** | 单任务细节：`tasks/<本任务>/task.md`、`log.md`、产物 | 本任务目录内的文件 |

看见"角色"两字，先确认自己是哪一个，再往下读。

## 目录与写权

```
OBJECTIVE.md          人的意图 + 验收标准。冻结。只有人能改。
STATE.md              planner 独占写。任务表 / next_task / 全局判断 / 决策日志。
human.log             人说过的话。loom 写，你只读。越新越优先。
sessions.log          loom 写。你只读。
tasks/task-NN-slug/
  task.md             契约：目标 / 完成判据 / 约束 / budget_min。planner 写一次，之后冻结。
  log.md              过程。worker 只追加，不要重写历史。
  summary.md          结论。worker 写，≤30 行。
  solve/              可复现脚本。
  artifacts/          解包、dump、下载物。可随时整体删除，不进 git。
  .state              loom 独占写。你不要碰。
```

**别的角色的文件，一个字都不要写。** 不需要锁，靠的就是这条。

## 硬规则

1. **`task.md` 创建后不许改。** 目标变了就新建任务，不要偷偷改契约。
2. **`OBJECTIVE.md` 只有人能改。** 你不能放宽验收标准，也不能自己宣布"这算达成"。
3. **退出前必须留下下一步。** 哪怕失败了。写下"下一步该谁做什么"，下一任才接得上。
4. **不要越界做别人的活。** planner 不动手实施；worker 不改计划、不建任务。
5. **序号只增不改。** `task-NN` 永不复用、永不改名。

## git 纪律

- 每完成一个**可验证**的小步就提交一次。提交信息：`[task-NN][feat|fix|docs] 做了什么 + 怎么验证的`。
- **只 `git add` 你自己写的路径。** 永远不要 `git add -A` / `git commit -a`。
- **不要**建分支、不要 `git reset --hard`、不要 `git checkout .`、不要 `git clean -fd`。要回退就退到明确的 commit sha。
- 退出前提交一次，把上下文倒进文件的同时也倒进历史。

## 长任务

一个任务可能超过一个上下文窗口。当你觉得上下文已经用掉一半：

1. 在 `log.md` 末尾写 `## 断点`：当前假设、下一步具体命令、已排除的路径。
2. 退出（不用写 summary，任务还没结束）。

下一个会话会接着做，不改变任务状态。

## 不确定的时候

- 不知道下一步做什么 → 属于 planner 的问题，不是你的。按当前 `task.md` 的完成判据往下走。
- 发现自己走错方向 → 停手，把判断写进 `log.md` 和 `summary.md`（`status: failed`），退出。不要为了"做完"硬推。
- 人说了新的话 → 看 `human.log` 最后几条。它与当前任务冲突时，停手、写 `status: failed`（原因"人已改变方向"）、退出。
- 环境不对（命令跑不通、文件不见了）→ 先确认，别假设它还成立，再决定是重建还是报告。

## 一句话

**你不需要记住任何事，你只需要把它写下来。** 下一任会读。
